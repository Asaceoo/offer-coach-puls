# offer-coach 技术手册

> 版本：v1.5.0｜ 更新：2026-10-24

## 1. 架构概览

offer-coach 是纯指令型 WorkBuddy Skill（无脚本依赖），采用三级渐进披露：

```
offer-coach/
├── SKILL.md                  # L2：触发 + 一键全出流程 + 红线 + 阶段门控（常驻触发后上下文）
├── references/               # L3：分析框架，按需加载
│   ├── job-analysis.md       # 四维分析框架 + 隐含信号对照表 + 英文 JD 规则
│   ├── match-framework.md    # 三分法诊断规则 + 定制简历衔接规则
│   ├── question-design.md    # 题量分配（15~20，6:5:4）+ 出题方法 + 禁止项
│   ├── interview-plan.md     # 通知解析字段表 + D-N 倒计时计划 + automation 提醒
│   └── review-template.md    # 复盘卡结构 + playbook 反哺规则
└── assets/templates/         # L3：9 个输出模板（唯一输出格式来源）
    └── profile / match-report / tailored-resume / question-bank / interview-plan / review / index / playbook / master-resume .md
```

## 2. 数据契约

运行期数据落在**当前工作区** `offer-coach/`（与技能目录分离）：

| 路径 | 写入者 | 消费者 |
|---|---|---|
| `jobs/index.md` | 一键全出、状态流转 | 每次会话启动时读取恢复上下文 |
| `jobs/{job-id}/*.md` | 对应流程 | 跨会话增量更新 |
| `resume/master.md` | 首次简历解析 | 所有匹配/定制流程 |
| `playbook.md` | 复盘流程自动合并 | 面试辅导押题引用 |

- job-id 规则：`公司简称-岗位简称-MMDD`；去重键 = 公司+岗位+地点+JD 相似度。
- 模板是唯一输出格式来源：填充时保留全部节标题，空节写"（无）"，保证可解析与 diff 稳定。

## 3. 关键设计决策

| 决策 | 理由 |
|---|---|
| 主简历一次解析、落 `master.md` | 避免每次上传/重复解析，跨会话复用 |
| 每条诊断必须引用简历原文 | 反虚构红线的可校验落地；无引用即违规 |
| 阶段门控（每步落盘再继续） | 会话中断可恢复；防止长流程跳步 |
| 题目给框架不给背诵稿 | 用户真实经历填充，避免面试撞车背稿 |
| 模板保留空节 | 结构稳定 > 篇幅省略，便于下游解析 |

## 4. 扩展点

| 能力 | 现状 | 扩展方式 |
|---|---|---|
| Word 导出 | 汇总时按需转交 workbuddy-docx | 无需改技能 |
| 面试提醒 | automation_update 一次性任务 | 用户拒绝则降级为计划内清单 |
| 云同步 | 未实现（本地 only） | 可接 cloud-service，注意简历属敏感个人信息 |
| 新行业题库 | 通用框架 | 调 question-design.md 的行业轨映射即可 |

## 6. 版本与发布

- 版本号唯一来源：仓库根 `VERSION`（格式 `vX.Y.Z`）。
- 打包：`python scripts/package.py`（patch +1）或 `--minor` / `--major` / `--no-bump`；自动同步两份手册首页版本行，产出 `dist/offer-coach-vX.Y.Z.zip`（排除鲁班优化数据文件与 .bak）。
- 发布：源码推 GitHub 主分支，zip 附到对应 tag 的 GitHub Release。
