# offer-coach 技术手册

> 版本：v1.9.0｜ 更新：2026-10-25

## 1. 架构概览

纯指令型 WorkBuddy Skill（无运行时依赖），三级渐进披露：

```
offer-coach/
├── SKILL.md                  # L2：触发 + 阶段0 + 一键全出流程 + 4 红线 + 失败分支表 + 加载指引
├── references/               # L3：7 个规则文件，按需加载
│   ├── job-analysis.md             # 四维分析 + 七问深读 + 深度调研纪律
│   ├── match-framework.md          # 三分法诊断 + 定制简历衔接（含改写强度红线）
│   ├── question-design.md          # 50 题七类 + 六层结构 + 命题方法论四问
│   ├── interview-plan.md           # 通知解析 + D-N 计划 + 押题 + 能量排程
│   ├── review-template.md          # 复盘卡 + 押题校准 + 反哺三动作
│   ├── positioning-and-stories.md  # 定位面谈 + 故事卡 + 押题校准 + 能量管理
│   └── offer-stage.md              # 谈薪 + 拒因三层归因 + 90 天护航
└── assets/templates/         # L3：13 个模板（唯一输出格式来源）
    └── report（六部分）/ positioning / story-cards / master-resume /
        tailored-resume / interview-plan / review / index / playbook .md
```

## 2. 数据契约

运行期数据落在**当前工作区** `offer-coach/`（与技能目录分离，全部本地）：

| 路径 | 写入者 | 消费者 |
|---|---|---|
| `positioning.md` | 阶段 0 定位面谈 | 投递判断（第一道筛子）、谈薪锚定 |
| `story-cards.md` | 定位阶段建立、复盘沉淀新战例 | 题库参考答案装填（第一素材源）、简历改写 |
| `resume/master.md` | 首次简历解析（一次解析反复复用） | 所有匹配/定制流程（引用锚点） |
| `jobs/{job-id}/report.md` | 一键全出（六部分中间稿） | PDF 渲染源；面试辅导引用题库节 |
| `jobs/{job-id}/tailored-resume.md` | 一键全出 | 用户投递使用 |
| `jobs/{job-id}/interview-plan.md` | 面试辅导流程 | 复盘（押题校准） |
| `jobs/{job-id}/review-{n}.md` | 复盘流程 | playbook 反哺、题库补充 |
| `jobs/{job-id}/offer-{n}.md` | 谈薪流程 | 用户决策 |
| `jobs/index.md` | 各流程 | 会话启动恢复上下文；**岗位状态唯一事实源** |
| `playbook.md` | 复盘反哺自动合并 | 面试辅导押题（顽固卡点置顶） |
| `exports/*.pdf` | 报告 PDF 渲染（md→HTML→打印） | 用户交付物 |

- job-id 规则：`{公司拼音/英文简称}-{岗位简称}-{MMDD}`，字母段 2~6 个小写字母；任何撞名（含跨年）先查 index 递推 `-2`/`-3`。
- 模板是唯一输出格式来源：保留全部节标题，整节无内容写"（无）"，字段无内容写"（未提供）"，落盘前自检无 `{ }` 占位符残留。
- 【待补：…】仅用于简历修改建议与答题思路示例两类场景。

## 3. 关键设计决策

| 决策 | 理由 |
|---|---|
| 定位先行（候选驱动） | 没有底线的分析是浪费；定位是岗位第一道筛子 |
| 六部分报告而非分散文件 | 用户要的是一份"投递决策书"，不是四个待拼装的文件；PDF 为最终形态 |
| 故事卡弹药库 | 参考答案一次装填全场复用；复盘持续增厚 |
| 一岗一报告铁律 | 防止多岗位信息污染；跨岗位统计只在 index/exports |
| 深度调研按需+纪律 | BOSS 信息与工商矛盾时以调研为准；查无实据标（未核实）禁编造 |
| 55 题左右八类而非 15 题三轨 | 术语/情景/案例/高频四类直击"不会答"而非"没看过" |
| 参考答案=真实素材装填 | 既给对照标准又不产背诵稿；亲历细节用户核实 |
| P0 精练卡（一页 A4） | 55 题×七层约 22 页，考前无法消化；精练卡只留 P0+待强化题的接化发骨架，把"报告厚度"与"考前可用性"分开 |
| 失败卡（SC-F） | 失败 probing 是压力题唯一无素材来源的一类；专用卡片字段让"讲失败"不靠编 |
| P0 双版本答案 | 面试官给 30 秒和给 5 分钟是两种考法，单版本适配差 |
| 彩排状态逐题标记 | 复盘回填新题后要知道「这题彩排过没有」，押题才能按 待强化>未彩排>经受住 排序 |
| 导出一律提示隐私纪律 | 报告含姓名/联系方式/薪酬底线，PDF 最易转发 |
| index 为状态唯一事实源 | report 第六部分仅快照，防双向漂移 |
| 阶段门控（每文件立即落盘） | 会话中断可恢复 |
| 谈薪/拒因/90天终局 | 教练 KPI 是试用期转正，不是入职当天 |

## 4. 输出链路（PDF）

`report.md` → markdown 库转 HTML（A4 打印样式）→ Edge headless `--print-to-pdf`（`--no-pdf-header-footer`）→ PyMuPDF 校验（页数/首尾内容/末题锚点/页脚残留/六部分结构）。**失败降级**：转换失败交付 report.md 并说明原因。中间件在 `_pdf_export/`（英文路径，规避中文路径 URL 编码问题）。

## 6. 扩展点

| 能力 | 现状 | 扩展方式 |
|---|---|---|
| Word 导出 | 汇总时按需转交 workbuddy-docx | 无需改技能 |
| 面试提醒 | automation_update 一次性任务 | 用户拒绝则降级为计划内清单 |
| 云同步 | 未实现（本地 only） | 可接 cloud-service，注意简历属敏感 PII |
| 新行业题库 | 通用框架 | 调 question-design 的八类映射即可 |

## 7. 打包与发布

`scripts/package.py`：自动递增版本号（patch/minor/--no-bump）→ 同步两份手册首页版本行 → 产出 `dist/offer-coach-vX.Y.Z.zip`。发布流程：git push main → REST API 创建 Release 并上传 zip 资产。
