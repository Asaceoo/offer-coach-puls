# offer-coach 技术手册

> 版本：v1.11.0｜ 更新：2026-10-26

## 1. 架构概览

纯指令型 WorkBuddy Skill（无运行时依赖），三级渐进披露：

```
offer-coach/
├── SKILL.md                  # L2：触发 + 阶段0 + 一键全出流程 + 4 红线 + 失败分支表(16 行) + 加载指引
├── references/               # L3：7 个规则文件，按需加载
│   ├── job-analysis.md             # 四维分析 + 七问深读 + 调研纪律（信源分级/保鲜/量化/关键人/缺口）
│   ├── match-framework.md          # 4.1 三分法 + 4.2 六维评估卡（填写规则+覆盖度自检）
│   ├── question-design.md          # 50 题八类 + 八层结构 + 接化发 + 失败素材管线 + 六维覆盖自检
│   ├── interview-plan.md           # 通知解析 + D-N 计划 + 押题（按六维查漏）+ 能量排程
│   ├── review-template.md          # 复盘卡 + 押题校准口径 + 反哺三动作 + 补彩排
│   ├── positioning-and-stories.md  # 定位面谈 + 故事卡（战例卡/失败卡）+ 押题校准 + 能量管理
│   └── offer-stage.md              # 谈薪 + 拒因三层归因 + 90 天护航
└── assets/templates/         # L3：13 个模板（唯一输出格式来源）
    └── report（六部分）· p0-card · positioning · story-cards · master-resume ·
        tailored-resume · interview-plan · review · offer · reject-note · onboarding-90 · index · playbook .md
```

## 2. 数据契约

运行期数据落在**当前工作区** `offer-coach/`（与技能目录分离，全部本地）：

| 路径 | 写入者 | 消费者 |
|---|---|---|
| `positioning.md` | 阶段 0 定位面谈 | 投递判断（第一道筛子）、谈薪锚定、六维③ |
| `story-cards.md` | 定位阶段建立、复盘沉淀新战例 | 题库参考答案装填（第一素材源）、六维②⑤ |
| `resume/master.md` | 首次简历解析（一次解析反复复用） | 所有匹配/定制/六维证据（引用锚点） |
| `jobs/{job-id}/report.md` | 一键全出（六部分中间稿） | 报告 PDF 渲染源；辅导流程引用题库节与 4.2 六维卡 |
| `jobs/{job-id}/p0-card.md` | 彩排后（步骤 4 内） | P0 精练卡 PDF（考前 24h 速查） |
| `jobs/{job-id}/tailored-resume.md` | 一键全出 | 用户投递使用 |
| `jobs/{job-id}/interview-plan.md` | 面试辅导流程 | 复盘（押题校准基线） |
| `jobs/{job-id}/review-{n}.md` | 复盘流程 | playbook 反哺、题库回填、补彩排 |
| `jobs/{job-id}/offer-{n}.md` / `onboarding-90.md` / `reject-note.md` | 终局流程 | 用户决策 |
| `jobs/index.md` | 各流程 | 会话恢复上下文；**岗位状态唯一事实源** |
| `playbook.md` | 复盘反哺自动合并 | 面试辅导押题（顽固卡点置顶） |
| `exports/*.pdf` | 报告 + 精练卡渲染（md→HTML→打印） | 用户交付物（含 PII，分享前需删联系方式） |

- job-id 规则：`{公司简称}-{岗位简称}-{MMDD}`，字母段 2~6 个小写字母；撞名（含跨年）先查 index 递推 `-2`/`-3`。
- 模板是唯一输出格式来源：保留全部节标题，整节无内容写"（无）"，字段无内容写"（未提供）"，落盘前自检无 `{ }` 占位符残留。
- 【待补：…】仅用于简历修改建议、答题思路示例、待补清单三类场景。

## 3. 关键设计决策

| 决策 | 理由 |
|---|---|
| 定位先行（候选驱动） | 没有底线的分析是浪费；定位是岗位第一道筛子 |
| 六部分报告而非分散文件 | 用户要的是"投递决策书"，PDF 是最终形态 |
| 4.1 三分法 + 4.2 六维卡并列 | 前者答"配不配"，后者答"面试官怎么给我打分"；六维各带证据/风险/怎么证明，并点名最弱维度 |
| 六维三层联动 | 报告层并列 → 出题层查漏补题 → 押题层最弱维度必押；否则六维卡只是装饰 |
| 故事卡 + 失败卡 | 压力题的"失败 probing"是唯一无素材来源的一类，专用卡片字段让"讲失败"不靠编 |
| 一岗一报告铁律 | 防止多岗位信息污染；跨岗位统计只在 index/exports |
| 深度调研默认执行 + 纪律六条 | BOSS 展示与工商矛盾时以调研为准；查无实据标（未核实）并转情报缺口 |
| 55 题左右八类 + 接化发 | 术语/情景/案例/高频/压力五类直击"不会答"而非"没看过"；接化发是结构不是台词 |
| 压力彩排 + 打穿判据 | 彩排预测的真实失败点与实战卡壳点可重合；判据三条防止"自演自评" |
| P0 精练卡（一页 A4） | 报告实测 13~20 页考前无法消化；精练卡只留 P0+待强化题的骨架 |
| 参考答案=真实素材装填 | 既给对照标准又不产背诵稿；亲历细节用户核实 |
| 导出隐私纪律 | 报告含姓名/联系方式/薪酬底线，PDF 最易转发 |
| index 为状态唯一事实源 | report 第六部分仅快照，防双向漂移 |
| 阶段门控（每文件立即落盘） | 会话中断可恢复 |
| 谈薪/拒因/90 天终局 | 教练 KPI 是试用期转正，不是入职当天 |

## 4. 输出链路（PDF）

`report.md` / `p0-card.md` → markdown 库转 HTML（A4 打印样式）→ Edge/Chrome headless `--print-to-pdf`（带 `--no-pdf-header-footer`）→ PyMuPDF 校验（页数/首尾/末题锚点/六维齐全/页脚残留/六部分结构）。**失败降级**：无 headless 浏览器时交付 md 并说明原因。中文路径需先复制到英文临时路径再传 URL。

## 6. 扩展点

| 能力 | 现状 | 扩展方式 |
|---|---|---|
| Word 导出 | 汇总时按需转交 workbuddy-docx | 无需改技能 |
| 面试提醒 | automation_update 一次性任务 | 用户拒绝则降级为计划内清单 |
| 云同步 | 未实现（本地 only） | 可接 cloud-service，注意简历属敏感 PII |
| 新行业题库 | 通用框架 | 调 question-design 的八类映射与六维覆盖即可 |
| 红队协议共用 | 压力题接化发内建于 offer-coach | 可与 grill-me 的追问协议抽公共层 |

## 7. 打包与发布

`scripts/package.py`：自动递增版本号（patch/minor/--no-bump）→ 同步两份手册首页版本行 → 产出 `dist/offer-coach-vX.Y.Z.zip`。发布流程：git push main → REST API 创建 Release 并上传 zip 资产。
