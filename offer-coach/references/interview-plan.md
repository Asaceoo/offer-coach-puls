# 面试辅导计划设计

触发：用户收到面试通知（文本/截图）。产出 `jobs/{job-id}/interview-plan.md`。

## 第一步：解析通知
从通知中提取以下字段，**缺失的一次性问齐**：

| 字段 | 说明 |
|---|---|
| 面试时间 | 日期 + 具体时间；相对今天的天数（D-N 表示法） |
| 轮次 | 一面/二面/HR 面/终面；二面以上要追问一面情况（引出复盘） |
| 形式 | 现场 / 视频 / 电话 |
| 地点/链接 | 现场地址或会议链接 |
| 面试官 | 姓名与职位，若有；据此推断面试侧重（技术官→岗位轨，老板→动机与稳定性） |
| 携带材料 | 简历份数、作品集、证书等 |
| 其他注意事项 | 着装、提前到场、笔试等 |

## 第二步：生成倒计时计划
按剩余天数生成任务清单，固定结构：

- **D-0（面试当天）**：出发前 30 分钟流程演练 + 押题 Top 5 快速过一遍 + 反问环节准备 2 个问题。
- **D-1**：押题重点（从 report.md 题库节选 8~10 题，标注"高概率出现"的理由）+ 自我介绍定稿（60 秒版 + 3 分钟版）。
- **D-3 / 更早**：关键缺口补课（对照 match-report）+ 公司调研（产品线、规模、口碑）+ 材料准备核对。

天数不足时合并（如明天面试 = 只有 D-1 + D-0），不要虚构不存在的天数。

## 第三步：提醒
主动提议用 automation 工具创建一次性提醒（面试前 2 小时，内容 = 地址/链接 + 材料 + 押题文档路径）。用户同意才创建；不同意就跳过，不要反复劝。

## 个性化引用
- 历史复盘卡（`review-*.md`）中的"下次第一个要改的动作"必须出现在计划里（若有）。
- `playbook.md` 的相关卡点引用进押题重点。
