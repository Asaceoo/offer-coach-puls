# 面试复盘设计

触发：用户面完一轮面试。产出 `jobs/{job-id}/review-{n}.md`（n = 轮次序号）。

## 收集方式
用户口述、粘贴、发截图均可。**缺什么问什么，一次问齐**：实际被问的问题、自己怎么答的、哪里卡壳、对方反应（追问/记录/皱眉/提前结束）、自己反问了什么。

## 复盘卡结构（固定模板 review.md）
1. **基本信息**：轮次、面试官、时长、形式。
2. **问题清单**：逐条记录实际问题（用户口述为准，不臆测）。
3. **表现标注**：每题标 ✔（答顺）/ △（勉强）/ ✘（卡壳或答错）。
4. **卡点分析**：✘ 和 △ 的题，分析卡的原因——知识缺口 / 表达混乱 / 经历空白 / 心态紧张，四选一或组合。
5. **对方反馈信号**：正面（追问细节=感兴趣）/ 负面（赶时间、泛泛而谈）。
6. **下一场第一个要改的动作**：单数、具体、可执行。"下次表现好点"无效；"自我介绍砍掉排比句，直接从产线降损数据讲起"有效。**这一条是复盘有效的唯一判据。**
   - 反例（禁止）："下次面试注意表达，更加自信。"（不可执行、无法验证）
   - 反例（禁止）："改进自我介绍、强化专业题、准备反问"（一次列三件，等于没有重点）
7. **本轮新题**：没押中、被问到的题 → 补入该岗位 question-bank.md。

## 落盘后的动作（必须执行，不要问）
1. 把"下一场第一个要改的动作"和卡点合并进 `playbook.md`（按主题归并，已有的不重复）。
2. 本轮新题补入 question-bank.md。
3. 会话里提示用户：下次辅导会自动引用这些卡点。

## 多轮复盘
每轮单独一张卡，不覆盖前轮。同一卡点连续出现 2 轮以上 → 在 playbook.md 中升级为"顽固卡点"，下次辅导计划置顶。
