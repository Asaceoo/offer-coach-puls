# 岗位四维分析框架

分析岗位时按以下四维展开，每个维度都要有 JD 原文依据（引用句子），不能凭空推断。

## 维度 1：岗位本质
用一句话回答"这个岗位到底在解决什么问题"。方法：把 JD 的职责条目归类，找出占比最高的一类，忽略修饰性措辞。
- 例：JD 写"负责品质体系维护、客诉处理、供应商辅导"→ 本质是"在客户与产线之间当消防员：防问题、灭火、追责源头"。

## 维度 2：核心要求
从 JD 提取 3~5 条硬性要求，分两类标注：
- **明示要求**：JD 直接写的（学历、年限、证书、软件）。
- **可推断要求**：从职责倒推的能力（写"处理客诉"→ 需要跨部门沟通 + 抗压）。
每条标注强度：★ 必须 / ☆ 加分。

## 维度 3：隐含要求（信号解读）
逐条扫描 JD 的措辞信号，常见对照：

| JD 措辞 | 隐含信号 |
|---|---|
| 抗压能力强、能接受加班 | 加班强度大或救火文化 |
| 沟通协调能力强、对接多方 | 扯皮多、需要软技能兜底 |
| 熟悉 XX 体系/认证 | 有体系审核压力，可能要陪审 |
| 快速学习、多任务并行 | 流程不规范、一人多岗 |
| 有 XX 行业经验优先 | 行业知识有门槛，如无经验需在简历/面试补认知 |
| 薪资面议 / 范围宽 | 定薪弹性大，谈判空间取决于面试表现 |

没有明显信号的 JD 写"（无明显隐含信号）"，不要硬凑。

## 维度 4：理想候选人画像
综合前三维，用 3~5 句话描述"面试官心里想找什么人"，供定制简历和面试准备对齐方向。

## 英文 JD 处理
- **全中文输出**：分析、结论、题库全部用中文。
- 专业术语、体系名、工具名首次出现时括注中文解释（如 FMEA 失效模式与影响分析、IATF 16949 国际汽车质量管理体系），正文以中文为主。
- 出题时同样遵循此规则（见 question-design.md）。

## 岗位深读七问（报告第一部分，结论先行）

分析岗位时除四维框架外，必须回答七个问题——这是从"档案"升级为"投递决策书"的关键：

1. **这个岗位到底是做什么的**：2~3 句大白话，不用黑话。公式：公司在产业链什么位置 + 岗位在公司什么位置 + 每天核心产出是什么。
2. **日常工作内容（典型一周）**：从职责倒推"每天实际在干什么"，4~6 项具体工作，标注高频/救火。
3. **公司真正想招什么样的人**：三个信号源交叉推断——JD 字面要求、公司阶段（扩产/规范化/救火，从调研的在招岗位全景与工商信息判断）、招聘者身份（老板亲招 vs HR 代招，BOSS 显示法人=老板直招）。写"面试官心里那张画像"。
4. **我与岗位匹配度**：一句话总判断 + 三个最强匹配点 + 两个最大短板，引用第四部分诊断。
5. **值不值得投**：明确结论（值得/可投可不投/不建议），理由对齐 positioning.md（无定位时基于岗位事实给方向性判断）。
6. **面试该重点准备什么**：按 P0 题列 3~5 条，指向题库题号。
7. **风险点与提前确认清单**：2~4 条风险信号 + 每条对应的面试确认问题。

**调研纪律**：BOSS 展示信息（规模/融资）可能与工商信息矛盾，以调研为准并在报告中注明差异；查不到写"（未核实）"，禁止推测填空。调研记录表固定记录六项（增加口碑与风险信号）；调研结论按 report.md 第二部分七项固定结构成文：公司概况/业务产品/行业地位与经营动态/组织与招聘信号/口碑与风险/对投递判断的影响/来源列表：工商信息/业务产品/招聘者身份/在招岗位全景/行业格局。
