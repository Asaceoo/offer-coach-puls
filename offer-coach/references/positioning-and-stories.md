# 定位与故事卡方法（阶段 0 核心，候选驱动而非 JD 驱动）

> 深化原则：教练不从 JD 开始，从"这个人要什么"开始。JD 只是定位的匹配对象。

## 一、定位面谈（首次使用必做，一次问齐）

五个问题，用户回答后落 `offer-coach/positioning.md`（模板 `assets/templates/positioning.md`；一次定位反复复用，与 master.md 同级）：

1. **目标岗位族**：你最想做什么方向？（可多选排序，如：品质 > 产品 > PMC）
2. **薪资底线与理想值**：低于多少不考虑？理想多少？
3. **地理范围**：能接受哪些城市/通勤半径？
4. **行业偏好与排斥**：想去哪些行业？坚决不去哪些？
5. **当前状态与能量**：在职/离职/空窗多久？每周能投入多少面试精力？

**定位的三个用途**：
- 岗位分析前先对照：JD 与定位冲突的岗位（如薪资低于底线、行业在排斥清单），直接提示用户"建议不投"，省下分析成本——**定位是岗位的第一道筛子**
- 精要版的"岗位一句话画像"增加一条：与定位的贴合度（贴/偏离/冲突）
- 面试辅导的谈薪策略从定位的底线/理想值出发

## 二、故事卡库（弹药库，8~12 张）

把经历拆成结构化故事卡，落 `offer-coach/story-cards.md`。来源优先级：用户口述的原始事实 > master.md 归一化内容 > 简历 PDF。**每张卡必须有用户确认过的数字与佐证**。

**卡片格式**（模板 `assets/templates/story-cards.md`）：
```
## SC-01 {故事名，动词开头}
- 事实：{时间/场景/我的角色/具体动作}
- 数字：{可验证的量化，标注来源}
- 结果：{结果 + 代价边界（牺牲了什么换来的）}
- 标签：{2~4 个能力标签，如：协调/救火/降本/带教/排产/数据/复盘}
- 佐证：{谁或什么能证明这事是真的（报表/邮件/同事/结果存续）}
- 待核实：（确认点：…）
```

**标签即索引**：面试题参考答案、简历改写、开场白、复盘话术，全部先查标签映射故事卡——**一次准备，全场复用**。标签覆盖不足（如没有"救火"类故事）时主动提示用户补素材。

**维护规则**：复盘发现新战例 → 新增卡片；卡片被面试实战验证有效 → 标记 ★ 高频弹药；两个卡片标签完全重叠 → 合并。**张数不足 8 张时不凑数**（反虚构优先于张数目标）：按实际张数落盘，附待补标签清单，引导用户补充后增量补建。

## 三、押题校准（让题库质量可测量）

每场面试前在 interview-plan.md 写"**押题预测**"（预测会问的题+准备的答案要点）；复盘时在 review-{n}.md 记录"**实际被问**"，对照计算押题命中率（命中/总数）。命中率连续两场 <40% → 题库生成策略需要检讨（行业轨/岗位轨权重）。

## 四、能量与排程

连续多场面试时，辅导计划必须包含能量建议：一天不超过 2 场现场面试；重要面试排在精力最好时段；连续挂 2 场后主动建议用户休整而非加投。面试是消耗战，可持续性优先于速度。
